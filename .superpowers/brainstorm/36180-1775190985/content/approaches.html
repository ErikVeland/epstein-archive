Migration Approaches

Three paths to full Tailwind removal with a prop-based Radix design system

A

Extend & Harden the Current System

Keep the BEM CSS + lq- prefix convention already established. Add a typed spacing/sizing prop system to Box, Flex, Stack (via CSS custom properties). Build all Radix-backed primitives (Dialog, Dropdown, Tooltip, Switch, Select) styled with the existing token variables. Migrate components in phases.

Pros

  • Low architectural risk — extends what's already working
  • Existing Surface, LqText, Flex CSS stays unchanged
  • Incremental — ship phase by phase without breaking anything
  • Button already follows this pattern

Cons

  • Spacing prop API must be hand-built (mapping to CSS vars)
  • Flex's inline-style approach is inconsistent — needs fixing
  • Barrel exports need cleanup (Grid, Stack, Button missing from index.ts)

⭐ Recommended

B

Adopt Radix Themes as the Foundation

Install @radix-ui/themes, which ships a complete prop-based system (Box, Flex, Grid, Text, Button, Dialog, Select, etc.) out of the box. Theme it to match the glass aesthetic using Radix's CSS token overrides. Replace the custom design-system/ components with the Radix Themes equivalents.

Pros

  • Massive reduction in custom code to write and maintain
  • Accessibility and keyboard nav come free with every component
  • Prop-based spacing/sizing/typography already done

Cons

  • Radix Themes opinionated defaults fight the glass aesthetic
  • Custom Surface/glass effects need significant CSS overrides
  • Throws away existing Surface, LqText, Flex work already done
  • Harder to customize deeply without fighting the library
C

Token-First, Components-Second (Big-Bang)

Freeze component work. First establish the complete token system (spacing scale, sizing scale, typography, color) as CSS custom properties. Then systematically rebuild every component category in strict order: tokens → layout → surfaces → typography → interactive → domain. No partial migrations.

Pros

  • Cleanest architectural result — zero drift or legacy
  • Token system informs everything downstream

Cons

  • Long feedback loop — nothing ships until the full system exists
  • High coordination cost across 100+ components
  • Risk: token choices prove wrong after you've built on them
